Banque de donnees - demo pour partenaire operateur (prototype en SIMULATION)

FONCTIONNALITE PRINCIPALE : forfaits illimites a duree fixe (modele europeen)
- Forfait "Illimite 7 jours" : 500 F
- Forfait "Illimite 30 jours" : 5000 F
Pendant la duree active, l'utilisateur telecharge des fichiers sans limite. Activer
un nouveau forfait pendant qu'un autre est deja actif prolonge la duree (cumul),
au lieu de l'ecraser. Un rond qui se remplit en haut de la page montre en un coup
d'oeil le temps restant avant la fin du forfait (100 % juste apres activation,
0 % une fois expire).

Espace de telechargement personnel : chaque utilisateur ajoute un fichier trouve,
qui reste disponible hors ligne. Cette fonctionnalite necessite un forfait illimite
actif (sans forfait, le telechargement est bloque avec un message explicite).

CE QUE L'APPLICATION NE FAIT PAS (important pour la demo)
- Elle ne fournit AUCUNE connexion internet reelle. Le "forfait illimite" est un
  drapeau interne au serveur, pas un vrai acces reseau. Personne ne peut se
  connecter a un reseau social grace a ce systeme tant qu'aucun operateur n'est
  branche derriere.
- Le paiement est simule : aucun argent reel n'est preleve.

POINT D'INTEGRATION OPERATEUR (pour Orange, Moov, etc.)
Dans server.js, cherchez le commentaire "Point d'integration operateur" au-dessus
de la liste PLANS. C'est exactement l'endroit ou, le jour d'un partenariat, on
remplacerait l'activation du drapeau "illimite" par un vrai appel a l'API de
l'operateur pour activer un forfait data reel sur la ligne de l'utilisateur.

LANCER EN LOCAL
  node server.js
  puis ouvrir http://localhost:3000
Node 18 ou plus, aucune installation de paquet necessaire.

IMPORTANT : le dossier "public" doit rester juste a cote de "server.js".
Si tu vois "Not found" ou une page vide, verifie d'abord que ce dossier
"public" est bien present et complet (index.html, style.css, app.js).

Variables utiles :
  PORT=8080                    changer le port
  DATA_FILE=/chemin/x.json     changer l'emplacement des donnees
  NODE_ENV=production          cookies Secure (HTTPS requis), bloque les paiements simules
  ALLOW_FAKE_PAYMENT=1         autorise quand meme les paiements simules en production (utile pour une demo en ligne)
  ADMIN_CODE=un-mot-de-passe-secret   voir ci-dessous "DEVENIR ADMINISTRATEUR"
  ADMIN_EMAILS=toi@exemple.com        methode alternative, voir ci-dessous

DEVENIR ADMINISTRATEUR : LE CODE ADMINISTRATEUR (methode recommandee)
A l'inscription, un champ facultatif "Code administrateur" apparait sous le mot
de passe. C'est UN SEUL code secret, defini par toi via la variable d'environnement
ADMIN_CODE, et connu de toi seul au depart :
1. Sur Render (ou en local), ajoute la variable ADMIN_CODE avec le code de ton
   choix, par exemple : ADMIN_CODE=mon-code-super-secret
2. Redemarre le serveur (sur Render : "Save, rebuild and deploy").
3. Inscris-toi normalement (nouvel e-mail + mot de passe), et dans le champ
   "Code administrateur", tape exactement ce code. Le compte est immediatement
   reconnu administrateur et redirige vers la page /admin.html.
4. Si tu veux donner l'acces admin a quelqu'un d'autre plus tard, il te suffit
   de lui communiquer ce meme code pour qu'il l'utilise a SA propre inscription.
   Laisser ce champ vide (le cas normal) cree un compte client ordinaire.
Un compte qui s'inscrit sans ce code, ou avec un code errone, reste un compte
client classique : aucune indication n'est donnee sur l'existence ou non d'un
code correct (securite).

Methode alternative : ADMIN_EMAILS (liste blanche d'adresses e-mail separees par
des virgules, sans espace) continue aussi de fonctionner exactement comme avant :
toute inscription ou connexion avec une de ces adresses devient automatiquement
administrateur, meme sans code.

INTERFACE ADMINISTRATEUR
Une page separee /admin.html montre : nombre de comptes inscrits, forfaits actifs,
fichiers stockes, revenu simule total, repartition des forfaits vendus, et la liste
de tous les comptes avec un bouton pour offrir un forfait a un compte (utile pour
demarrer la demo avec un compte deja actif) et un bouton pour supprimer un compte.
Un lien "Administration" apparait a cote de l'adresse e-mail en haut de la page
principale des que le compte connecte est administrateur.
Un compte administrateur ne peut pas etre supprime depuis l'interface (protection).

SECURITE
- data.json contient les comptes (mots de passe chiffres) et les fichiers des
  utilisateurs. Ne le partage jamais et ne le publie jamais (deja exclu par .gitignore).
- Le code administrateur (ADMIN_CODE) est compare en temps constant pour eviter
  les attaques par mesure de duree de reponse ; ne le partage que par un canal
  de confiance (jamais par e-mail en clair ni publiquement).
- Chaque fichier est limite a 10 Mo, et chaque utilisateur a 200 Mo d'espace total.
